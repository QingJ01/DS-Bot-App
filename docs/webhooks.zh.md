# Webhook 回调

Webhook 让 DS Bot 之外的服务能够联系你的团队。该服务向 DSH 主机上的一个地址发送 POST
请求，内容会作为一条用户消息送达某个 Bot 的对话或某个群聊，就像你自己发送的一样。Bot
随后按平常的指令、工具和记忆作出回应。

Webhook 默认关闭，需要你主动开启。它属于主机插件，不属于手机桥接，并使用独立的端口。

## 开启

在配置文件的 `bot` 条目中加入 `hooks`。

**DSH 补丁会整体替换 `bot.config`，不会合并嵌套字段。** 添加 `hooks` 时请保留该配置中
已有的所有选项，并把这个与机器相关的文件放在仓库之外。

```yaml
- id: bot
  config:
    hooks:
      enabled: true
      host: 0.0.0.0
      port: 8790
      publicUrl: https://hooks.example.com
```

| 选项 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `false` | 是否开启监听。关闭时不会监听任何端口。 |
| `host` | `127.0.0.1` | 绑定的地址。`0.0.0.0` 表示接受本机之外的请求。 |
| `port` | `8790` | 绑定的端口。 |
| `publicUrl` | 绑定的地址 | 当前面有域名或反向代理时，写入可复制地址的来源。 |

修改文件后请重启主机。端口被占用不会影响 DS Bot 运行，Webhooks 页面会显示监听失败的原因。

## 创建 Webhook

在手机应用中打开 **设置 → Webhooks**，点按 **＋ 新建 Webhook**，为其命名，选择送达的
Bot 或群聊，并可按需填写消息模板。主机会返回一次密钥，请立即复制：主机只保存摘要，
之后无法再次显示。

一个团队最多可有 50 个 Webhook。插件通道上也提供相同的操作：`hook-create`、
`hook-update`、`hook-delete`、`hook-rotate` 和 `hooks-list`。

## 发送请求

向该地址发送 POST 请求，并在 `Authorization: Bearer` 头中带上密钥：

```sh
curl -X POST "$URL" -H "Authorization: Bearer $SECRET" \
  -H "content-type: application/json" \
  -d '{"text":"构建 42 已通过"}'
```

- JSON 正文可以包含 `text` 或 `message`，其余内容会以 JSON 原样传递。
- 非 JSON 正文会原样传递。
- 无法设置请求头的服务可以用 `?token=` 代替。
- 模板中的 `{{text}}` 会替换为服务发送的内容，`{{name}}` 替换为 Webhook 名称。未填写
  模板时，Bot 看到的是 `[Webhook: <名称>] <发送的内容>`。
- 只响应 POST。超过 64 KB 的正文会被拒绝，单个 Webhook 每分钟最多 120 次请求。

消息交给团队后返回 `202`；密钥错误返回 `401`；Webhook 不存在或已停用返回 `404`；正文
过大返回 `413`；发送过快返回 `429`。无论哪种情况，响应中都不会再次出现密钥。

## 注意事项

- **除非确有需要，请绑定回环地址。** `0.0.0.0` 会在所有网络接口上开放端口，凡是能访问
  该机器的对象都可以尝试该地址，此时密钥是唯一的防线。
- **在前面加一层 TLS。** 监听使用明文 HTTP，而 GitHub 之类的服务不会接受自签名证书。
  请在反向代理或私有 VPN 上终止 TLS（参见[手机的 HTTPS](mobile.zh.md)），或让监听只绑定
  回环地址后再转发。
- **密钥可能泄露时请立即轮换。** 轮换后旧密钥立即失效。
- **Webhook 是消息，不是决定。** 它以用户身份到达，不会回答问题，也不会批准工具，Bot
  仍需要自己的批准才能执行操作。
- **投递不会重写团队文件。** 投递次数保存在内存中，主机重启后从零开始。
