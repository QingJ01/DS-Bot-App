# 备份与迁移团队

团队值得留存：有哪些 Bot、每个 Bot 被交代做什么、跑在哪个模型上、在哪里工作、权限与每日预算。**导出**会把这一切写进一个文件，**导入**再把它放回去——可以放回同一台 DSH，也可以放到另一台机器。

```sh
# 在 <home>/exports/ 写入备份，并在响应中返回内容
curl -s localhost:PORT/api/bot -H 'content-type: application/json' \
  -d '{"endpoint":"team-export","payload":{}}'

# 把备份放回去：可以是导出内容本身，也可以是该目录下的文件名
curl -s localhost:PORT/api/bot -H 'content-type: application/json' \
  -d '{"endpoint":"team-import","payload":{"path":"team-2026-10-17T09-12-00-000Z.json"}}'
```

`<home>` 是 DS Bot 的数据目录（Linux/macOS 为 `~/.dsh/bot/`，Windows 为 `C:\Users\<user>\.dsh\bot\`）。导出文件就是普通 JSON，可以放进私有仓库、加密保存或放进磁盘带走——请把它当作笔记看待：里面是指令和名称，没有密钥。

## 会带上什么

| 会带上 | 不会带上 |
| --- | --- |
| 每个 Bot：名称、角色、指令、外观、模型、思考等级、权限预设、工作目录、每日预算、能力 | 会话 ID 与会话历史 |
| 每个群聊：名称、成员、管理员、回复模式、公告、工作目录、权限预设 | Bot 之间的往来消息，以及会话回答过的问题 |
| — | 秘密（保存在 `secrets.json`，永不离开主机） |
| — | 记忆：`memory/bots/<id>/MEMORY.md` 及其主题属于该 Bot 自己的历史 |

导入进来的 Bot 拥有同样的设置和**全新的对话**。这正是导出的意义：你精心调好的就是这些设置。若想连记忆一起迁移，请在导入后把 `memory/bots/<id>/` 复制到新 Bot 的 id 目录旁。

## 导入的行为

- **只新增，不替换。** 团队里已有的同名 Bot 会被区分开：导入的成为 `Writer 2`，原有的分毫不动。
- **群聊按本机现有成员组建。** 本机没有的成员会被报告并略过；成员不足两个的群聊会被跳过，而不会建成半个群。名称已被占用的群聊会变成 `Crew (imported)`。
- **本机不提供的模型、不存在的目录会被报告并略过。** Bot 仍然会到达：它会等待你选择模型（与创建时未选模型的行为一致），并先在团队工作区工作。
- **本机没有的能力会被报告并略过**，Bot 的其余设置照常应用。
- **不会悄悄做一半。** 任何与文件不一致之处都会作为说明返回，并标明所属的 Bot 或群聊。
- 只有持有团队的宿主可以导入；仅观察另一个 dsh 团队的宿主仍可导出，因为那是只读操作。

## 需要注意

- **导入不是合并。** 两个团队的 Bot（各有自己的 Main Bot 规则与记忆）会合成一个普通 Bot 的团队。之后请在 Bot 详情中把需要的提升为 **Main Bot**。
- **指令可能很长。** 导出会完整保留它们；这是用户主动要的文件，不是传输格式。
- **文件保存在主机上。** 导入只读取 `<home>/exports/` 内的文件名，绝不接受任意路径：导入不能成为读取主机任意文件的手段。
