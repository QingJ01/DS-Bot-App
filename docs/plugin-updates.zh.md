# 更新主机插件

中文 · [English](plugin-updates.md)

电脑打开 **DS Bot 设置 → 插件更新**，手机打开 **设置 → 插件更新**。「关于 DS Bot」也保留相同入口。这里升级电脑上的插件；手机 App 需要从 Releases 单独更新。

1. 点击「检查更新」，查看已安装版本和最新完整发布，包括 `v0.1.1-r2` 这样的修订版。
2. 电脑点击「更新」；手机点击「更新主机插件」，再点击「安装更新」。
3. 等待安装结果。如果提示重启，请在电脑上完全退出并重新打开 DSH；如果已立即生效，重新加载电脑窗口，手机断线时重新连接即可。

更新器统一从本仓库的 GitHub Releases 查找更新，支持原先通过包名、本地压缩包、远程压缩包和固定 GitHub 提交安装的用户。安装前验证发布对应的固定源码提交、包名、版本与仓库，再调用 DSH 公开的插件管理接口。不会误装 npm 上游同名包。开发链接、源码目录、分支检出和自定义分支仍由用户自行维护。

## 修复安装

当前版本已是最新发布版时，可点击「修复安装」，确认后重新安装该发布版，保留 Bot 团队和对话。同版本但无法识别来源的提交只提供显式修复，不会静默覆盖；不会把更高版本降级到旧发布版。

安装时明确指定依赖名，例如 `ds-bot@github:QingJ01/DS-Bot-App#<完整提交>&path:ds-bot`，让 pnpm 在解析前替换旧压缩包依赖，避免再次读取历史下载链接的错误校验值，以及远程压缩包缓存缺失 integrity 的问题。每次更新固定到具体提交，不覆盖已发布压缩包、源码标签或原校验值。

更新器不会删除整个配置锁文件、清理共享缓存、关闭校验、移除其他插件或自动批准构建脚本。安装和失败恢复交由 DSH 管理；失败后可以重试，网络限流、包校验、版本兼容、磁盘空间、文件占用和构建审批会显示对应处理提示。其他依赖本身损坏时，仍可能需要在 **Harness 插件页**处理。

插件只在 `bot/update-receipt.json` 保存成功安装的版本、源码提交、安装文本和时间，不包含凭据或聊天数据。安装完成但需要重启时，尚在运行的旧插件会继续显示重启提示。

此更新器目前在主分支，等待新版本发布。旧版若无法使用原有更新器，需要先按[安装指南](getting-started.zh.md)安装一次包含此功能的版本，后续即可在插件内更新。

## 开发验证

升级测试夹具不进入发布包，只能在显式命名的 `.dsh-test-*` 目录运行。它先为测试环境复制独立插件，再替换故意损坏的压缩包锁记录。先跑常规 smoke，再做真实升级，最后关闭环境：

```sh
cd ds-bot
UPDATE_SMOKE=1 CONTEXT_WINDOW=100000 CHECK_RATIO=0.45 dev/bench.sh update-proof 3137 8837 reset
node dev/smoke.mjs update-proof 3137
node dev/update-smoke.mjs update-proof 3137
dev/bench.sh update-proof 3137 8837 stop
```

需要可访问网络，且已有不低于当前源码清单版本的正式发布。测试通过 DSH 安装真实固定提交，检查旧坏依赖已移除、团队和用户文件保留。`scripts/test-github-install.py` 还覆盖实际更新安装文本、其他依赖、用户文件和 frozen-lockfile 重装。
