# 旁路问答（btw）

- 日期：2026-10-21
- 相关：#407

## 为什么

Bot 干活动辄几分钟到几十分钟。用户想「顺便问一句」时，普通输入框由 DSH 提供，消息按 busy-Enter 偏好排队或插队：排队要等当前回合结束才被读到；插队会改变 Bot 当前的路线；两种都永久进入对话历史，之后每一轮重复计费。Claude Code 在 2026-03 用 `/btw` 验证了这类需求：用当前会话的完整上下文做一次无工具、单轮的独立调用来回答，不打断主任务、不写入主对话历史；请求与会话自己的请求保持同构，能复用提示缓存的前缀（是否命中取决于提供方）。

Bot 之间也有反方向「拉」事实的需求（我需要对方掌握的事实，而团队规则里 `message_bot` 的约定是「推」），但那条线（`ask_bot`）改动已定的派活设计，另行提案，不在本设计内。

取舍：

- btw 只回答，不动手。不执行任何工具，读不了新文件、改不了任何东西，天然安全。
- 答案是「基于目前已有进展」的快照：回合在飞的步骤看不到，和 Claude Code 的语义一致。
- 不进模型可见历史，但在界面留痕：用户随时能查问的是什么、答了什么，结果可检查。
- 请求与该会话自己的请求保持同构（同路由、同思考强度、同工具声明）：保留会话请求的前缀，提高提示缓存复用的机会，交接笔记（`writeNote`）就是这么做的。

## 已定的行为

### 快照

- 快照取该会话当时的请求头（路由与思考强度）、派生消息、工具历史和会话标识，几样一起取走，避免拼装到一半会话变了。快照含的是已提交到 Session 的历史；DSH 的持久化是异步缓冲的，快照不等待落盘。
- 只取到「工具调用都已有结果」的边界：DSH 先提交含工具调用的 assistant 消息再执行工具，所以正在执行、结果未齐的那一批（连同那条 assistant 消息）不进快照。DeepSeek 的 adapter 会拒绝结果缺失的工具调用历史。
- 快照之外在飞的步骤看不到：答案可能落后于 Bot 正在做的事，卡片上固定标注。

### 无工具的调用

- btw 请求与会话自己的请求保持同构：同路由、同思考强度、同工具声明和工具历史，只在末尾追加 btw 问题；输出上限同样沿用快照路由的配置——思考与答案共享输出预算，btw 自定的低上限会让思考模型的答案经常在完成前被截断。
- 因为带着工具声明，btw 的提示词明确写明「只回答，不要调用任何工具」；host 不执行任何工具：模型返回的工具调用块一律不派发。允许重试一次；第二次仍返回工具调用即失败，卡片显示失败原因。重试的那次调用同样计入用量。
- 答案若自称执行了操作，不可信（btw 不会执行任何工具）；卡片固定标注「基于目前已有进展的回答，没有执行任何操作」。

### 人对 Bot 的 btw

- 在 Bot 的私聊里，输入以 `/btw ` 开头（后跟问题）就是旁路提问；Bot 忙或空闲都可用。
- 入口走 DSH 的输入触发机制（input trigger 的 `matchSpace`/`matchEnter`/`matchClaim`）：普通输入框归 DSH 所有，不能靠 DS Bot 自己的 `api/bot` 发送路径拦截。认领后立即受理：答题在后台进行，输入框不停在提交状态，卡片先显示「正在回答」，答案到达后填入。
- 认领失败的输入绝不落入正常发送。下面三种情况都在认领后拒绝（按契约抛出拒绝：输入框里的内容原样保留、并提示原因）：群聊里输入 `/btw`（btw 只在 Bot 私聊可用）；带附件（btw 不支持附件）；只有 `/btw` 没有问题时（提示写上问题）。
- 回答用快照里的路由与思考强度，与产生这份上下文的请求一致。Bot 从未跑过模型、快照里没有路由时，拒绝并提示先正常对话一次。换了模型之后，btw 仍用快照里的路由；该路由的提供方已不可用时调用失败，卡片显示原因。
- 这次问答不写进该 Bot 的模型可见历史：主对话上下文不变，正在跑的回合不受影响、不改变路线。
- btw 卡的呈现分两处：回合还在跑时，卡片出现在输入框上方的专属泊位（`conversation.composer.dock`），带取消按钮；回合结束后，卡片移到快照边界所在回合的回合尾（`conversation.chat.turnTail`，DS Bot 的回合分隔已在用它）——同一时刻只有一处可见。btw 不是会话的转录条目，不能插在转录中间；旧分段的卡片并入 DS Bot 自己渲染旧分段的 EarlierParts 路径，仍挂在原分段的原回合处。
- 卡片可折叠（问、答、时间），用户可见、模型看不到。问题与答案整段保留；卡片按分段存在自己的文件里，不写进团队状态文件；团队视图只带当前分段的卡片，更早分段的卡片随那一段的历史一起加载。不设条数、字数和并发上限。
- 卡片上可以取消：中断这次调用。DSH 重启后，读到的未完成 btw 标为失败。
- 调用计入用量页，kind 为 `btw`；模型调用失败时卡片显示失败原因，没有其他副作用。达到输出上限时，本次问答标为失败，保留已生成的部分答案，并注明答案因输出上限而未完成。

## 不做什么

- 不在群聊里开放 btw，也不对群会话做快照。
- btw 不执行工具；要动手就走主对话。
- 不做多轮旁路对话，不能追问；要继续讨论就用主对话。
- 不把 btw 的内容写进该 Bot 模型可见的上下文，不写进记忆，也不事后推给它的回合。
- 不做 Bot 对 Bot 的旁路问答（`ask_bot`）：它改动派活设计里「只提问不动手留给独立 app」的决定，另行提案，需维护者确认。

## 已知限制

- 快照只含已提交到 Session 的历史，且截断到「工具调用都有结果」的边界；回合在飞的步骤看不到，答案可能落后于 Bot 正在做的事。
- 提示缓存是否命中取决于提供方；同构只能保留前缀、提高复用机会。未命中时，一次 btw 是一次全上下文调用的输入成本；答案的输出和可能的一次重试也照常计费。
- 带着工具声明时模型仍可能返回工具调用：不执行，重试一次，再犯即失败。
- 回合在跑时回合尾槽位尚不存在（DSH 在回合结束后才发布它），所以在跑的卡片先在输入框上方，回合结束后归位回合尾。
- 总量不设上限，靠用量页和 btw 卡可见。
