# 移动端六项功能

本轮实现以 DS Bot 自有代码及 Harness `dsh-v0.2.1-alpha.1` 公开服务为基础，没有修改 Harness。主机需要保持运行。Android 测试包及主机插件必须一起更新；更新插件后重启 DSH，才能加载新的桥接和桌面浏览器代码。

## 界面与工具结果

聊天输入区提供并排的 Skills、桌面浏览器入口；等待用户回答、主机运行和网络连接分别显示。DS Bot 原创角色支持眨眼、触摸反馈和工作动画，遵守降低动态效果设置，并在 App 进入后台后停止动画。

展开工具消息可查看终端、文件、差异、检索、网页、技能和任务卡片；未知工具保留通用卡片。终端清除 ANSI 颜色控制，文件提供行号，文件修改区分新增/删除与执行失败，检索及网页提供用户点击的来源链接，任务显示完成状态。卡片保留复制、原始详情、错误、耗时和结果截断标记。展示的数据仍来自主机脱敏后的有限投影，不会在手机执行工具返回的脚本。任意第三方工具的自定义 DOM 界面没有自动移植。

## Skills

在聊天中打开 Skills，查看当前 Bot/Agent 会话作用域内的目录和可由用户调用的技能正文。点“使用”只把 `/技能名` 填入草稿，由你确认发送；Harness 按真实用户消息处理指令注入，主机工具权限保持生效。模型专用技能可以显示元数据，但不能从手机伪造用户调用。

“自有技能库”支持新建、编辑和确认删除 Markdown 指令，保存到 DS Bot 自己的主机数据目录。并发编辑通过 revision 检测冲突。自有库最多 100 个技能，每个正文最多 64 KiB；名称使用 kebab-case。已有项目、用户或插件提供的同名技能优先，手机不会改写它们的文件。自有技能可分别设置是否允许模型和用户调用。技能指令不应包含凭据；凭据使用主机的 Secrets/credentials 功能。

## 插件管理

设置 → Harness settings → Manage plugins。可查看并启停插件与套件，检查待安装包、确认安装、查询安装阶段/结果、取消尚可取消的安装，以及确认移除可移除的包。

注册表包在检查后固定到具体版本。依赖构建脚本必须单独选择批准，再确认重试。包操作使用设备范围的请求 ID，断线后查询原任务；不会自动重复安装。DS Bot 自身及 Harness 标记为受保护的包不能在这里卸载。插件代码在主机执行，安装可能重启插件并短暂中断连接。

本轮验证了真实主机的插件清单及安装/取消等公开接口契约；没有在用户主机安装第三方插件。任务跟踪保存在当前桥接进程，主机重启后若无法查询原任务，应先核对主机安装状态，再决定下一步。

## 桌面浏览器控制

1. 在 DSH Desktop 中打开目标 Bot 的浏览器，点击“允许手机控制此浏览器”。该开关默认关闭，只作用于当前窗口和 Bot，不写入永久偏好。
2. 在手机打开这个 Bot 的聊天 → 桌面浏览器。支持标签列表、新建、切换、关闭、导航、前进/后退、刷新/停止和滚动。
3. “读取当前页面”显示正文和可交互控件。输入需要确认填入，点击需要确认操作。点击/输入后快照失效，继续操作前重新读取页面。
4. 电脑端关闭开关或退出窗口后，新的手机控制会被拒绝。

登录状态和 Cookie 保留在电脑上。接口只接收固定操作，不接受 JavaScript 或 CSS 选择器；控件引用有快照校验，隐藏、失效或敏感输入不能操作。导航保留原版地址检查与云元数据地址阻止；列表展示的网址去除查询串、片段及用户凭据。当前交互快照覆盖主文档及开放的 Shadow DOM，不控制跨域 iframe。一次请求丢失回执后应刷新状态，不能假设没有执行。每个桥接进程最多保留 2000 条浏览器命令回执，达到限额后需重启桥接。

已通过真实 Harness → 窗口通道 → 受控 Chromium 页面，以及真实手机界面的读取、输入和确认点击检查。原生 Electron WebView 和 Windows/macOS Desktop 的实机检查仍待进行。

## 移动通知

设置 → 通知中心。主机收集新回复、待回答问题和工具审批，保存最近 500 条通知元数据，手机显示最近 100 条可见通知。已读、提醒开关与类别按设备保存；撤销设备后无法继续读取或接收推送。当前最多跟踪 200 个逻辑会话。进入后台后不依赖手机持续运行 WebSocket。

App 内通知中心可直接使用。“允许前台系统提醒”申请原生系统通知权限，在 App 前台时提醒其他对话的新事件。系统提醒只使用通用标题和提示，不发送对话正文、工具输出、模型凭据或桌面 Cookie。

### 后台运行时提醒：无需 EAS、FCM 或 APNs

在通知中心点击“开启后台运行提醒”。手机直连 DSH 插件的通知接口，收到新回复、提问或审批元数据后发出本地系统通知。平台推送凭据不是这条路径的前置条件，仍需 HTTPS 配对、允许系统通知和保持 DSH 主机运行。

- **Android**：原生前台服务保持后台接收，通知栏显示“DS Bot 后台通知已开启”，可直接点“停止”。服务约每 10 秒检查通知；网络断开时退避至最多 60 秒并显示重连状态。切换到其他 App 后接收工作不依赖 React Native 的 JS 定时器。关闭开关、断开主机、划掉 App 或强制停止会停止本地接收；不会在开机或被系统终止后偷偷重新启动。
- **iOS**：原生后台任务在系统允许的短暂后台时间内接收。时间到后释放后台任务并显示暂停状态，回到 App 后恢复；没有滥用后台音频或位置能力来保持运行。要在 App 被 iOS 暂停后持续提醒，需要配置 APNs/Expo 云推送。
- Android 的省电、Doze 和厂商后台管理可能延迟网络或终止服务；常驻服务不是“永不被杀”的保证。Android 11 云端模拟器已实测 Home 后收到系统通知、App 内关闭后停止服务；运行时通知和原生生命周期仍需实体设备验收。

接收服务使用仅允许读取通知元数据的独立登记，不拿聊天、工具执行或刷新会话的权限。登记只在主机和手机内存保留，最长 24 小时；不写入文件、Intent 参数或日志。设备撤销、关闭提醒、重新登记或主机重启后旧登记失效。App 回到前台并连接成功后，会依据之前的选择恢复登记；主机重启而手机仍在后台时，需要回到 App 完成重连。Android 通知栏手动停止的选择会保留，不会在下次打开时自动重新开启。

类别开关和已读记录同样适用于运行时提醒；开始接收时从当前通知游标起步，不重复弹出已经记录的旧通知。一次积压只弹最近三条，其他事件保留在通知中心。点击通知会核对主机标识并打开对应会话。退出连接会停止本地接收，并尝试关闭主机登记；主机离线时云推送登记不能保证立即撤销，可在主机端撤销设备。

### 可选云推送：App 不运行时也可提醒

后台云推送采用可选的 Expo relay，只有明确登记此设备后才发送。开启云推送后停止常驻接收，避免两条路径重复提醒。未配置 EAS 时此按钮禁用，不影响通知中心、前台提醒或后台运行提醒。

后台推送还需完成以下部署配置：

1. 在自己的 Expo/EAS 项目中配置 Android FCM v1 和/或 iOS APNs 凭据及对应的应用标识。平台私钥通过 EAS 凭据管理配置，不放入 Git 或聊天。
2. 构建 App 前设置公开的 `DS_BOT_EAS_PROJECT_ID` 环境变量。Android 还需设置 `DS_BOT_GOOGLE_SERVICES_FILE`，指向与 `app.dsbot.mobile` 对应的 Firebase 客户端 `google-services.json`，再重新 prebuild/构建原生应用；这个文件不等于发送端的 FCM 服务账号私钥。项目 ID 属于公开配置；FCM/APNs 凭据不是项目 ID。仓库提供 `eas.json` 的 preview（Android APK）和 production（Android App Bundle）配置，iOS 凭据由 EAS 管理。
3. 用 HTTPS 配对主机，允许系统通知，点击“开启系统推送”，再点“发送测试通知”核对实际收件。

云推送路由登记仅保留在主机内存；App 会保存用户选择，并在恢复连接且系统权限仍有效时重新登记，不把推送 token 写入项目文件。Expo 接收请求不代表 APNs/FCM 已在手机投递，系统限制也可能延迟通知。当前测试 APK 未配置 EAS/FCM/APNs，包含 Android 运行时接收模块，但不能宣称 App 关闭后仍能收到云推送。

验证范围与产物校验值见 [验证记录](mobile-validation.zh.md)。

## 工作目录与上游 v0.1.5

v0.1.1 已同步上游 v0.1.5。在 Bot 或群聊详情打开「工作目录」，可选择主机已知项目、输入完整主机路径，或在主机提供目录浏览器时逐级浏览。Bot 可重置为「团队工作区」，群聊可恢复「各 Bot 自己的目录」。这些是电脑上的路径，不是手机存储；主机拒绝 DSH 数据目录及包含它们的父目录。

切换目录后，Bot 对话在新分段继续，历史保留；群成员从下一轮群内任务起切换。Bot 自己或 Main Bot 通过工具改变目录时，仍保留上游扩大写入范围的审批检查。手机界面作为已配对用户发起设置，不替代或绕过 Bot 工具审批。

手机工具结果支持 PTC 子工具状态、交付文件卡片，以及主机仍保留的文件变更摘要。卡片显示路径、描述与记录的增删行数；主机文件路径不是手机下载地址，不会直接打开电脑原生对话框或提供任意文件读取。消息里的普通附件继续使用经过身份与可见引用校验的下载、预览流程。

## 群聊统一权限与工作进展（主分支）

上游 v0.1.6 的同步目前在主分支，尚未包含在已发布的 v0.1.1-r2 安装包中。使用配套的新插件和 App，在群聊详情的「权限」打开「全员统一」，选择主机提供的权限预设；关闭后恢复各 Bot 的个人权限。只有用户可设置，Bot 无法通过工具更改。

群成员执行多步任务时，会在群内同步进度并在完成后返回结果。聊天里只显示一个工作状态胶囊，点击进入详情可查看成员当前任务、分段切换和待审批状态，并停止该群里的成员工作。状态与审批按群隔离，不显示其他群或个人会话的工作。
